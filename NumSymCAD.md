# NumSymCAD — Integrated Numeric/Symbolic Circuit Analysis Environment

## Vision

NumSymCAD is a unified environment for circuit design and analysis that combines:

- **Symbolic analysis** (SLiCAP) — Laplace transforms, pole-zero, noise, sensitivity,
  transfer functions; results rendered as LaTeX expressions and tables.
- **Numeric simulation** (NGspice) — operating point, AC, transient, DC sweep, noise;
  results returned as NumPy arrays for post-processing.

The **Python instruction file** is the unifying element.  A single `.py` script can
call both engines, post-process their results, and generate publication-quality plots
— all in one place.  The schematic editor provides the circuit; the instruction file
drives the analysis.

---

## Schematic types

Two schematic types coexist in the same project:

| Type | Extension | Symbols | LaTeX rendering | Analysis engine |
|------|-----------|---------|-----------------|-----------------|
| SLiCAP | `.slicap_sch` | SLiCAP symbol set | yes | SLiCAP (symbolic) |
| NGspice | `.spice_sch` | NGspice symbol set | no | NGspice (numeric) |

- Both schematics live as **dockable canvas widgets** inside one `QMainWindow`.
- Each canvas has its own toolbar and symbol library; they can be tiled, tabbed, or
  floated independently via the View → Panels menu.
- Preferences (grid, snap, display style, LaTeX scale, …) are stored and applied
  **per schematic type**; switching the active canvas restores the correct context.
- The project is shared; `ini.project_path` is the same for both canvases.
- The instruction file references each schematic by name, e.g.:

  ```python
  import SLiCAP as sl
  sl.make_netlist("design.slicap_sch")   # SLiCAP netlist  → txt/<stem>.cir (SLiCAP format)
  sl.make_netlist("design.spice_sch")    # NGspice netlist → cir/<stem>.cir
  ```

> **Note:** SLiCAP calls makeNetlist() trough makeCircuit() which returns a circuit object that will be used for SLiCAP instructions.

## Plots

Plots are generated by `sl.plot()`, `sl.bode()`, `sl.plot_noise()`, and similar calls
in the instruction file.  Each call opens a **floating matplotlib window** that stays
open until the user closes it.

Plot size is controlled by SLiCAP.ini settings (`plot_fontsize`, `plot_linewidth`,
`fig_width_*`, `fig_height_*`, …) and set explicitly per call so that the output
matches the target LaTeX figure type (margin figure, single-column, full-width) without
scaling artefacts.  An embedded panel would override `figsize` and break font/linewidth
consistency across figure types — this is why there is no waveform panel.

> **Note:** We can use the existing SLiCAP plots (backwards compatible) and use sl.plot() also for ngspice plots, thats what I do now after selecting traces from ngspice2traces(). The only thing is that we have to put the cursor option into all the SLiCAP plot functions (except poles and zeros (scatter plots)). In polar plots we need to have another cursor method displaying magnitude, angle and the contour variable (usually frequency)

## Goal functions

A **goal function** reduces a swept+stepped result to a single scalar per step value,
then assembles those scalars into a trace that can be plotted with the step variable
on the x-axis.  This gives an immediate visual answer to questions like:
"how does the RMS output noise vary with bias current?" or
"at which supply voltage does the peak gain exceed 40 dB?".

### Concept

Given a stepped NGspice result dict (layout: `{x_key: 1-D, step_key: 1-D, signal: 2-D}`):

```
step values:   [p_0,  p_1,  …,  p_{N-1}]          ← x-axis of goal trace
signal:        [[y_00, y_01, …],                   ← row 0: sweep at p_0
                [y_10, y_11, …],                   ← row 1: sweep at p_1
                …]
```

A goal function `g` maps each sweep row to one number:
`goal_values[i] = g(x_sweep, signal[i, :])`

The result is a plain SLiCAP `trace([step_values, goal_values])` that plugs directly
into `sl.plot()`.

### API

Goal functions are passed via the `goal_fn` argument of `ngspice_instr2traces()`
(or `ngspice_dict2traces()` for a raw result dict):

```python
BW = sl.ngspice_instr2traces(AC1, trace_type='dBmag',
                             goal_fn=sl.goal_bandwidth(-3))
```

When `goal_fn` is provided and the result contains 2-D stepped signals, each step row
is reduced to a scalar via `goal_fn(x_sweep, y_row)`.  The returned trace has *step
values* on the x-axis and goal values on the y-axis — ready for `sl.plot()`.
For 1-D (un-stepped) signals `goal_fn` is ignored.

### Built-in goal functions

These live in `SLiCAPngspice.py` alongside `ngspice_goal_trace` and can be passed
directly as `goal_fn`:

| Function | Formula | Typical use |
|---|---|---|
| `goal_rms(x, y)` | `sqrt(trapz(y², x) / (x[-1] - x[0]))` | Integrated noise, distortion |
| `goal_mean(x, y)` | `trapz(y, x) / (x[-1] - x[0])` | Average value over sweep range |
| `goal_peak(x, y)` | `max(abs(y))` | Peak gain, worst-case overshoot |
| `goal_peak_freq(x, y)` | `x[argmax(abs(y))]` | Resonance frequency vs. bias |
| `goal_at_x(x0)(x, y)` | `interp(x0, x, y)` | Value at a fixed frequency/time |
| `goal_bandwidth(level)(x, y)` | `x` on falling edge where `y` drops `level` dB below the peak | −3 dB bandwidth vs. step |

`goal_at_x` and `goal_bandwidth` are **factory functions** — they return a
`goal_fn`-compatible callable:

```python
BW = ngspice_goal_trace(result, 'v(out)',
                        goal_bandwidth(-3),   # −3 dB point
                        trace_type='dBmag')
sl.plot("bw_vs_R", "Bandwidth vs R", "lin",
        {"BW": BW}, xUnits="Ω", yUnits="Hz", show=True)
```

## LaTeX output panel

SLiCAP functions such as `sl.eqn()` and `sl.table()` write **self-contained LaTeX
snippets** to `tex/SLiCAPdata/` and equivalent RST snippets alongside them.  The
design document (`report.tex`, `report.rst`) owns structure, styling, and bibliography;
it pulls in live data via `\input{SLiCAPdata/filename.tex}` or `.. include::`.

**HTML output is deprecated.**  The panel is a lightweight snippet viewer:

- After each instruction run it lists (or shows) the files written to
  `tex/SLiCAPdata/` this session.
- Clicking a file shows its raw LaTeX/RST source in a `QPlainTextEdit` — enough to
  confirm the expression or table looks correct without compiling the full document.
- No `QWebEngineView`, no HTML rendering.

> **Note:** SLiCAP has a built-in LaTeX formatter and a built-in RST formatter (see www.slicap.org). Preview of LaTeX tables and expressions can be done using the LaTeX formatter. Saving those snippets to the tex/SLiCAPdata/ subdirectory makes them ready for import into a LaTeX documents.

### Phase 5 — Add SLiCAP instruction dialog

**New file:** `slicap_analysis_dialog.py` — `SLiCAPAnalysisDialog`

**API reference** (from www.slicap.org):

All `do*` functions share the same signature:
```python
sl.doLaplace(cir, source='circuit', detector='circuit', lgref='circuit',
             transfer='gain', convtype=None, pardefs=None, numeric=False,
             stepdict=None)
```
- `source` / `detector` / `lgref`: `'circuit'` (from netlist) | refDes string | list of two (differential)
- `transfer`: `'gain'` | `'asymptotic'` | `'loopgain'` | `'servo'` | `'direct'` | `None`
- `convtype`: `None` | `'all'` | `'dd'` | `'cc'` | `'dc'` | `'cd'`
- `pardefs`: `None` | `'circuit'` | `{sym: expr, …}`
- `numeric`: `False` (symbolic) | `True` (float)
- `stepdict`: `None` | `{'stepmethod': 'lin'|'log'|'list'|'array', 'params': …, …}`

**Which parameters are active per analysis type:**

| Function | source | detector | lgref | transfer |
|---|---|---|---|---|
| `doLaplace` | ✓ | ✓ | ✓ | ✓ |
| `doPZ` | ✓ | ✓ | ✓ | ✓ |
| `doNoise` | ✓ | ✓ | — (ignored) | — (ignored) |
| `doSolve` | — | — | — | — |
| `doMatrix` | — | — | — | — |

`convtype`, `pardefs`, `numeric`, `stepdict` are always active.

**Pre-flight: build the circuit object before opening the dialog**

`makeCircuit()` parses the netlist and returns a `circuit` object that carries all the
information the dialog needs to populate dropdowns (sources, nodes, controlled sources).
This must happen before the dialog opens, analogous to how the NGspice dialog pre-builds
the netlist and extracts `output_vars`.

In `window.py _on_slicap_add_instruction()`:
```python
from SLiCAP.SLiCAPmath import makeCircuit
self.statusBar().showMessage("Parsing circuit…")
try:
    cir = makeCircuit(str(self._slicap_path))   # or the .cir stem
    sources   = _slicap_sources(cir)    # independent V/I sources
    detectors = _slicap_detectors(cir)  # node names + dependent var names
    lgrefs    = _slicap_lgrefs(cir)     # controlled sources (E, G, F, H)
    params    = _slicap_params(cir)     # circuit parameters for stepdict
except Exception:
    sources = detectors = lgrefs = params = []
finally:
    self.statusBar().clearMessage()
dlg = SLiCAPAnalysisDialog(cir_var="cir", sources=sources,
                           detectors=detectors, lgrefs=lgrefs,
                           params=params, parent=self)
```

Helper functions `_slicap_sources`, `_slicap_detectors`, `_slicap_lgrefs`,
`_slicap_params` live in `window.py` (or a small `slicap_circuit_info.py` helper).
They inspect `cir.elements` and `cir.nodes`.

**Dialog structure:**

- **Analysis type** (tab widget): `doLaplace` | `doPZ` | `doNoise` | `doSolve` | `doMatrix`
- **Circuit variable** field: Python name of the `circuit` object in the instruction

- **Result variable** field: Python name for the result (default: `LAPLACE1`, `PZ1`,

- **Per-tab controls** (disabled/hidden when ignored by the function):

  - `detector` combo, pre-populated from `detectors` list, editable
  - `lgref` combo, pre-populated from `lgrefs` list, editable
  - `transfer` combo (`gain` | `asymptotic` | `loopgain` | `servo` | `direct`)
- **Common controls** (always visible):
  - `convtype` combo (`None` | `all` | `dd` | `cc` | `dc` | `cd`)
  - `pardefs` radio (`None` | `'circuit'` | custom dict)
  - `numeric` checkbox
  - `stepdict` section (collapsible): method, params combo (from `params` list),

- `snippet() -> str` returns `<result> = sl.<func>(cir_var, ...)` with only
